# 工坊场景与动作反馈

本轮恢复背墙抽签票看板，补充巨龙对白低吼、完整身体投影和物品操作过渡。声音、模型、动画均为本项目自制。

## 抽签票

[原作官方 10 月 7 日公告](https://steamcommunity.com/app/5245810/allnews/)明确区分墙上的加票／移票和铁砧最终强化概率。`game.ticketDisplay(anvilSwordOrNull)` 与实际抽签共用原始票数计算，分别显示五类结果的基准、遗物加票、机制加票、移除和当前票数，以及盲骰、红粉笔、累计大成功等效果。没有将最终百分比乘一千来冒充原始遗物票数。

看板位于后墙，采用羊皮纸、深色墨迹与等比例 SVG 方格，设施入口可聚焦查看。按原作参考，每种结果只有一行：基础票为空心方格，直接遗物加票接在后面，以绿色方格与「＋」表示；移除票直接在已有票上打叉，不重复绘制移除栏。机制加票以相同绿色方格显示在对应结果下方的独立短行。方格是主要表达，右侧小计与底部总数辅助核对。方格以 SVG 图案平铺，完整行与最后部分行保持精确计数；大量累积票不会增加成千上万个 DOM 节点。默认查看不再遮挡看板，手机可打开等比例的大字票纸。空铁砧显示基准票。各票数规则沿用现有社区整理参数，板面排版为中文适配，未声称逐像素复制原版。

机制短行独立显示局内永久票、剑的成长与继承票、累积大成功票，以及盲骰、红粉笔、第三眼、满蓄能魔力核和条件转换等已生效贡献。点击「加票来源」可展开具名来源，每个来源继续以方格显示贡献。静态直接遗物增减与条件／临时机制分开记账，两者合计严格等于实际原始票数；跨过基础票的移除也会继续划销遗物或机制票。存档未保存累积票的历史遗物归属，因此使用准确的聚合名称。等级加权和概率转换留在铁砧百分比层。

羊皮材质由 `src/parchment.js` 统一生成：长短不一的裁切轮廓中穿插细小刀口，叠加纤维、皮面斑驳、暗色毛边和轻微折痕。墙面使用透明纹理与相同轮廓的薄皮模型，切掉的角落能看到后方砖墙；手机票纸也使用透明皮边，中文与方格独立绘制。纹理固定生成并缓存，更新票数不会重新随机纸面或模糊文字。

## 动作与投影

- 拾剑、放下、落砧、上架和摆贡台沿平滑轨迹过渡，保持同一个模型根节点；相机移动时手持目的位置随相机更新。
- 加热先插剑、渐热、抽出；仅铁、钢、锈蚀金属烧红，木、骨、魔力材质保留自身颜色。抽出之后金属持续红热，真实游戏热量仍只有原来的 0／100 两种状态。
- 普通锤击在约 320ms 接触剑刃，同时产生火星、光闪、声音和结果；进化和碎裂画面也到接触时更新。剑身震动使用每次挥锤的实际接触时间，快速构筑随节奏缩短。游戏结果先计算并存储一次，视觉延迟不产生额外随机抽签。
- 铁砧使用独立锻造待机姿势，进入时平滑举锤。锤面高举到剑面上方至少 70cm，再加速落下，接触后短促回弹；落槌不在接触前减速停顿。前臂 34cm、上臂 38cm，靠肘关节弯曲完成动作。桌面镜头移近铁砧，竖屏沿剑身斜向构图，手臂不再随镜头距离放大。桌面、方形与竖屏视角的整个挥锤轨迹均在固定肩点的伸手范围内。
- 用锤头端面接触实际剑刃，锤头、手掌和两段袖管在挥动过程中避开铁砧。命中时进化会重新查询新形态表面，火星与初始回弹也跟随新表面；待机帧缓存静态剑面的局部落点，避免每帧重新射线遍历整个模型。参考视频与观测范围见 [单手锤击参考](hammer-motion-references.md)。
- 动画总时长根据现有挥锤间隔缩短，最快握柄／风箱组合不会被视觉 busy 延长。
- 阴影有头、躯干、围裙、双腿和双臂；手臂与真实持剑、挥锤姿态关联。身体不写入第一人称颜色或深度画面，使用独立深度材质投影。
- 手机继续使用 DPR ≤1.5、主阴影 512；完整身体使用局部 256 阴影和少量几何，火星不增加阴影光源。

身体投影使用墙内、梁下的向下聚光灯，避免正交方向光的投影范围包含屋顶后遮住整片地板。票板镜头在桌面与触屏横屏保持居中；竖屏可通过「放大票纸」阅读，每种结果沿用墙面的一行布局。

加热结束才提交 `game.heat()`；离开炉火、开菜单或切换合约会取消未完成加热。动作时拦截重复物品操作，暂停冻结动作，换合约清理尚未完成的击打。视觉数据不进入存档格式。

## 声音

Web Audio 生成低频声带、次谐波和过滤的湍流气音；每句对白替换上一句，贡税结算与结局也按怒气播放低吼。沿用声音开关。静音、跳过导览、关闭结算和页面隐藏停止低吼。没有采样原视频音轨。

## 验证范围

回归覆盖动作原点、接触一次、暂停、加热取消、重入、身体投影资源、票数增减和音频节点停止。锤击几何检查覆盖薄厚剑、桌面／方形／竖屏及普通／最快节奏；实测锤面下降速度明显增加，固定骨长和肩点无需伸长来够到剑。浏览器连续录像检查高举、落槌、接触和回弹。500 组混合遗物构筑的最终概率摘要与修改前一致。

浏览器以普通 UI 操作验证拾剑、加热、落砧、单击敲打、票板、取消加热与存档继续；Web Audio 调试事件检查实际运行的音频上下文与对白播放节点。手机检查使用 Chromium 尺寸与粗指针模拟，未将其宣称为实体 iPhone／Android 音量或性能测试。发布信息见 `docs/cloudflare-deployment.md`。
